## 深度观察

**DeepSeek 把操作系统的老办法，搬进了 Agent 调度层。**

10 月 31 日晚，DeepSeek Harness 团队发布《Towards a More Autonomous Agent System》，并开源验证性原型 dsh-superagent-prototype。它要解决的不是"模型会不会写代码"，而是"一个人同时盯十个 Agent 时，注意力先崩溃"。方案是五件套：Router/Worker 双层架构、事件驱动、异步多信道交互、计算与状态及环境分离、外部 Watchdog。

关键数字：在约 300 条群聊与 CI 消息（含约 20 个真实工作请求）的合成负载上，Super-agent 的 p50/p95 完成时间为 12.4/15.7 分钟，而带 Subagent 工具的单会话 p95 达 29.5 分钟；取消"订阅直通"后 Router 决策数增加约 30%、读缓存 token 从 2323 万涨到 3177 万；Router 批处理把单个决策分摊的推理时间从 6.4 秒压到 1.6 秒。架构上，Router 只做分派与全局记忆、不配执行工具，Worker 才是隔离干活的一层；同一 PR 或 IM 话题的后续事件经订阅直通 Worker，不再回到 Router。

为什么重要：当 Agent 从"一问一答"变成"常驻、并发、主动"，瓶颈从模型能力转到会话管理与上下文同步——这与操作系统几十年前处理进程调度、缓存、看门狗的问题同构。对开发者的直接影响是，"Session"从产品概念退化为实现细节：用户只在 IM 或 PR 里说话，系统自己决定派几个 Worker、谁订阅哪条线程。

不确定性同样明显：实验基于合成负载与简化环境，作者自称"仅作初步参考"；单 Router 何时需要水平切分、多实例间 A2A 如何划上下文、云端 Agent 接入本地凭据带来的注入风险，四个开放问题都没有答案。它是原型，不是产品。[智东西](https://www.zhidx.com/p/606311.html)、[GitHub](https://github.com/deepseek-ai/dsh-superagent-prototype)
