# 产品方向：趋势 × 需求的阶段性结论

> **目的**：回答「AI 如何进入企业、产品研发应该以什么形态和方向」。这份文档不是行业综述，而是把 [landscape.md](landscape.md)、[demand-and-pain-points.md](demand-and-pain-points.md)、[target-enterprise-profile.md](target-enterprise-profile.md)、[hypotheses.md](hypotheses.md) 与 `ai-news/` 的趋势观察，收敛成可执行的产品判断。
>
> **性质**：阶段性结论（v0.3，2026-11）。每条结论给出置信度、前提与止损条件；被证伪时按 [hypotheses.md](hypotheses.md) 的规则更新，不删除旧判断。
>
> **证据**：外部来源 `[S#]` 见 [sources.md](sources.md)；内部趋势观察 `[N1][N2]` 见 [sources.md](sources.md) 的「内部趋势观察」一节。`[N#]` 只用于趋势背景，不用于市场事实。

## 0. 一页纸结论

**一句话：不做通用 Agent / Bot / 办公平台；做「垂直工作流里的、可审计的文档/任务 Agent」，从 F2 文档自动化切入，长成 F4 任务型 Agent，最终嵌入 F3 垂直工作流系统。**

| 决策 | 结论 |
| --- | --- |
| **首选切口** | 中型律所/企业法务的「特定合同审查 + 条款知识库 + 复核流」（默认）；有工程渠道则优先「工程投标/施工资料」，有财税渠道则优先「代账龙头」 |
| **目标客户** | 法律 20—200 人精品所 / 100—500 人企业的法务部；工程 100—800 人区域企业；代账 50—500 人区域龙头 |
| **产品形态** | v0 文档进 → 风险清单/修订建议 → 人工复核 → 审计日志；v1 客户条款库/Playbook；v2 嵌入 Word/WPS/OA/合同系统 |
| **收费** | 按份 / 按任务 / 年费 + 用量；先收费试点，不做免费 PoC |
| **目标** | 90 天 3 家付费试点；12 个月 30 家付费、续费 ≥70%、审查时长 −40%、单份成本 < 售价 50% |
| **明确不做** | 通用助手、通用桌面 Agent、通用办公助手、通用 Agent 平台、通用 Bot、医疗诊断、制造排产主流程、电商内容红海、纯项目制定制 |
| **止损** | 90 天拿不到 3 家付费试点 → 换切口，不改「垂直工作流」方向 |

> 以上数字是**验证目标**，不是市场事实；定价与指标需在试点中校准。

## 1. 为什么现在：供给侧的三个变化

### 1.1 Agent 正在从「问答」变成「常驻执行」，编排层在商品化

- DeepSeek 开源的 Super-agent 原型把「Router/Worker、事件驱动、订阅直通、存算分离、Watchdog」做成可复用的调度架构；实验 p50/p95 为 12.4/15.7 分钟，对比单会话 p95 29.5 分钟。团队自称是原型，不是产品。[N2]
- Vercel 发布 agent-desktop，让 Agent 操作用户整台电脑，而不只是浏览器。[N2]
- 以 IM/PR 为入口的常驻 Agent 开始成为产品形态：可被 @、可订阅线程、可主动执行任务（如 DeepSeek 原型）。[N2]

**产品含义**：多 Agent 编排、常驻执行、computer-use 会逐渐变成基础设施，而不是差异化产品。**不要做「更强的通用 Agent 平台」**；把编排能力当作底座，去做一个具体工作流里的可靠交付。

### 1.2 资本周期收紧，「廉价 token」不能当作长期假设

- OpenAI 把本轮融资目标从 300 亿美元下调至约 200 亿美元，估值从 1.4 万亿降至 1.25 万亿美元；纳斯达克 100 单日下跌 3.5%、10 月累计跌 6.65%。[N1]
- 超大规模厂商的算力承诺与债务继续膨胀，行业对「算力—收入—更高估值」的闭环开始重新定价。[N1]
- 直接后果：便宜推理的补贴来自便宜资本；融资收紧后，模型价格战会放缓，高频、高 token 场景的配额与价格可能收紧。[N1]

**产品含义**：不要做「token 消耗大、价值不可计量」的通用聊天/写作；从第一天就按任务核算成本，设计按份/按任务/按结果的计价，保证单位经济成立。

### 1.3 能力越强，责任、安全、审计越贵

- Wiz 记录 AI 开发平台的「黑色十月」：至少 9 家平台披露安全事件，多指向凭据窃取、agent swarm 攻击与「蒸馏」入侵；两起案例在 30/13 小时内发起约 80 万/170 万次 Bedrock 调用，标价计费超 10 万美元。[N1]
- 企业侧：36% 没有正式 AI 治理，88% 已让 AI 在无人工签核下做决定；97% 高管称部署 Agent，但只有 52% 员工真正使用，29% 承认抵制。[S3][S20]
- 医疗、法律、金融的顾虑集中在幻觉、隐私、权限与责任归属。[S10][S11][S18]

**产品含义**：**信任层不是「功能」，是产品的一部分**：权限、审计、复核、引用、私有化、责任边界。谁能让「不敢用」的行业敢用，谁就能收溢价。

> 注：OpenClaw、WorkBuddy、Personal Agent 集群、DeepSeek super-agent 的形态演化，已整理为 [trend-agent-evolution.md](trend-agent-evolution.md)（[N3]）。下面的 1.4—1.6 只取与产品方向直接相关的结论；外部事实沿用该整理稿，未重新核验。

### 1.4 三类趋势对产品研发的含义

| 趋势 | 代表 | 可借的力 | 不要做的陷阱 |
| --- | --- | --- | --- |
| computer-use / 桌面 Agent | OpenClaw[N3]、Vercel agent-desktop[N2] | 把「操作电脑」降级为垂直工作流里的一个工具调用；让 Agent 去填表、导数据、改文档 | 做通用桌面 Agent：权限、安全、可靠性、跨软件兼容会被平台和大厂拖死 |
| 办公 Agent / 企业上下文 | WorkBuddy[S23]、千问办公[S22] | 借办公入口分发；把产品嵌进 IM/文档/审批流 | 做通用办公助手：被大厂免费捆绑，独立产品没有留存理由 |
| Bot / IM 入口 | 各类 bot[N3]、DeepSeek 常驻 Agent 原型[N2] | 用 IM/PR 作为低门槛入口；让用户在原有工作流里 @ 一下就用 | 把「bot」当产品：没有行业知识、复核、审计，就只是一个更贵的聊天框 |

**结论**：这三类趋势都在把「通用能力」变成基础设施。产品研发要借它们的力（入口、编排、工具调用），但**产品本体必须是垂直工作流 + 责任链**，否则就会被商品化。

### 1.5 四代 Agent 的形态演化：从 OpenClaw 到 super-agent

> 完整整理见 [trend-agent-evolution.md](trend-agent-evolution.md)（[N3]）；这里只取与产品方向直接相关的结论。

| 代际 | 样本 | 形态 | 证明了什么 | 暴露的问题 |
| --- | --- | --- | --- | --- |
| 能力验证 | OpenClaw（2026-01） | 开源、可自托管的个人 Agent | Agent 可以操作真实电脑；IM 可成为入口；Skills 可扩张 | 安全边界、长任务可靠性、运维责任在用户 |
| 组织化 | WorkBuddy（2026-03，10 月企业版） | 办公智能体平台 | 企业要的是身份/权限/审计/私有化；个人提效 ≠ 组织回报 | 系统难打通、不敢放权、不好管控、难以常驻 |
| 产品化 | Personal Agent 集群（2026-08/09） | 常驻个人 Agent | always-on 形态成立；任务列表/审批/记忆成为主界面 | 可靠性、常识、成本、信任；同质化快 |
| 基础设施化 | DeepSeek super-agent（2026-10） | Router/Worker 运行时 | 调度、订阅、隔离、授权可以做成基础设施 | 原型；单 Router 扩展、多租户、凭据风险未解 |

**六条规律**：委托变长决定形态；交互面外移、Session 退化为实现细节；执行环境独立化；每次能力跃迁补一层治理；计费单位随委托长度上移；组织两端（超级个体/超级组织）同时生长。[N3]

### 1.6 趋势结论 → 产品决策

> A = 入口型 Copilot，B = 交付型数字员工，C = 底座型 Agent 运行时；定义见 [trend-agent-evolution.md](trend-agent-evolution.md) 第 4 节。

| 趋势结论 | 对我们的含义 | 选择 |
| --- | --- | --- |
| 竞争从模型转向运行时/治理 | 不自研通用 runtime；用现成模型与编排，把治理做进垂直产品 | 做 B 交付型数字员工，不做 C 底座 |
| 委托变长、界面外移 | 主界面是任务列表/审批/执行记录；IM/PR 是入口，不是聊天框 | 合同审查队列 + 复核 + 审计日志 |
| 每次能力跃迁补治理 | 审批、身份、审计、回滚从 v0 就有，而不是上线后再补 | 先收费试点，先过安全评审 |
| 计费单位随委托长度上移 | 按份/任务/结果计价，不按 token | 按份/按任务/年费 + 用量 |
| 企业从可度量、可审计的单点开始 | 选高频、必经、可度量、可审计的楔子，不做通用助手 | 法律合同审查；工程/代账备选 |
| B 被低估、A 被高估、C 壁垒最高 | 做垂直交付，不做入口 Copilot/通用平台 | B；不碰 A/C |

**取舍说明**：趋势研究说「运行时与治理是下一个战场」，但这是对大厂/平台团队说的。创业团队如果去做 C（通用运行时），会同时面对 WorkBuddy WMA、云厂商和开源的竞争；做 A（入口 Copilot）会被平台吞并。最可守的是 B：用别人的 runtime，把行业知识、复核、审计和交付做成产品。这与第 2、3 节的垂直判断一致。

**不做的边界**：这四代样本正好对应四类陷阱——OpenClaw 式通用桌面 Agent 的安全/运维责任、WorkBuddy/千问式通用办公助手的入口战场、Personal Agent 式通用 Bot 的同质化、无监督自主（G2 仅 7% 买家愿意给完全自主权）。[N3]

## 2. 为什么是垂直：需求侧的四条硬约束

1. **企业不为「AI」付费，为「被解决的工作」付费。** 买家语言是工时、单据、合规、回款，不是模型能力。[S3][S5]
2. **采用面宽、嵌入浅。** 近九成企业至少一个职能用 AI，44% 全企业部署，但只有 46% 嵌入核心工作流；Menlo 称仅 16% 部署是真 Agent。[S1][S2][S3]
3. **试点到生产是死亡谷。** 约 95% 的大型企业生成式 AI 试点没有可测量损益影响；员工实际使用率 52%，29% 抵制。[S20]
4. **中国第一约束是价格与交付。** 小微净利率 4.4%，58.5% 因价格放弃/停止续费；中小企业 AI 渗透率约 15%，68% 停留在轻量场景；政策方向是「小快轻准」、可私有化、可迁移。[S5][S6]

**结论**：通用能力会被大厂与开源吃掉；独立产品最可守的位置是 **「行业知识结构化 + 系统记录 + 责任链 + 交付服务」** 四件事的组合。[S18][S19][S21][S22][S23]

## 3. 交汇点：趋势 × 需求 = 产品机会地图

| 供给侧趋势 | 需求侧约束 | 产品含义 |
| --- | --- | --- |
| 通用 Agent/编排能力商品化 | 企业不为「自主」付费，为「结果」付费 | 不做通用 Agent，做垂直工作流里的任务 Agent |
| computer-use / 桌面 Agent 兴起 | 企业要求权限、审计、可回滚 | 先做「可复核的文档/数据任务」，不碰无监督的物理/资金动作 |
| 模型价格与配额不确定 | 中国客户价格敏感、要按效果 | 按份/按任务计价，单位任务成本可核算 |
| 大厂把通用助手捆进办公套件 | 通用问答/写作被免费化 | 避开 F1 通用副驾，切 F2/F3 的行业最后一公里 |
| 安全事件与合规压力上升 | 医疗/法律/金融「不敢用」 | 私有化、权限、审计、责任边界成为卖点 |

**一句话**：**Agent 是实现手段，工作流与责任才是产品。** 产品研发的重点不是「让 Agent 更自主」，而是「让一个具体工作流更可靠、更可审计、更省钱」。

**研发投入原则**：不自研基础模型/通用 Agent 框架；用现成模型与编排，把工程投入放在行业知识、评测集、系统集成、复核/审计与交付。

## 4. 候选切口：评分与取舍

> 评分为 1—5 的判断值，不是统计测量；权重体现「先活下来」的顺序：需求强度 25%、付费意愿 20%、数据/可复核 20%、竞争空隙 15%、交付可行性 10%、扩展性 10%。

| 切口 | 需求强度 | 付费意愿 | 数据/可复核 | 竞争空隙 | 交付可行性 | 扩展性 | 加权分 | 判断 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| A 法律：特定合同审查 + 条款知识库 | 5 | 4 | 5 | 2 | 4 | 5 | **4.25** | 默认首选；竞争最激烈，必须窄 |
| B 工程：投标/施工资料 | 5 | 4 | 3 | 4 | 3 | 4 | **3.95** | 竞争空隙更大；有工程渠道则优先 |
| C 财税：代账票据—记账—申报 | 5 | 3 | 5 | 2 | 3 | 4 | **3.85** | 高频、渠道强；价格战与现有软件压制 |
| D 医疗：病历/环境记录 | 5 | 4 | 3 | 3 | 2 | 4 | **3.70** | 需求最真；合规/EHR 集成/责任最重 |
| E 制造：预测维护/质检 | 4 | 5 | 2 | 4 | 2 | 4 | **3.60** | 价值高；OT/硬件/零容错，落地慢 |
| F 电商：内容/运营 | 4 | 2 | 4 | 1 | 5 | 2 | **3.05** | 红海、价格战，不做主方向 |
| G 通用 Agent/Bot | 4 | 2 | 3 | 1 | 4 | 3 | **2.85** | 大厂/开源正面战场，不做 |

**读法**：

- A 总分最高，但「竞争空隙」只有 2 分；如果做「通用法律 AI」，会被现有玩家和大厂夹击。**A 的前提是「窄」**：1—2 类合同、特定客群、客户自己的条款库、复核流、私有化。
- B 的竞争空隙更大，但需要工程行业专家/渠道；如果团队有建筑资源，B 的实际胜率高于 A。
- D/E 的需求与付费都强，但交付门槛（合规、EHR、OT、硬件）不适合作为软件团队的第一个产品；有行业资源时再考虑。
- F/G 不作为主方向：F 是红海，G 是平台战场。

## 5. 首选方向 A：法律合同审查 + 条款知识库

### 5.1 客户与切口

- **客户**：20—200 人的精品所、100—500 人企业的法务部；优先有大量重复合同、有外部律师费/人力预算、合伙人或法务负责人能拍板的组织。
- **切口**：先做 1—2 类高频合同（如买卖/服务/建设工程/劳动/保密），不要做「全品类合同审查」。
- **用户**：初级律师/法务专员（每天用）；合伙人/法务负责人（买单与定标准）。
- **痛点**：审查慢、条款底线散落在个人、重复审查、版本比对、漏条款、外部律师费高。[S10][S18]
- **现有替代**：初级律师、模板、关键词检索、通用大模型（不安全、不可追溯、不可审计）。

### 5.2 产品形态（12 个月）

| 阶段 | 形态 | 关键能力 | 不做什么 |
| --- | --- | --- | --- |
| v0（0—3 月） | F2 文档自动化 | 上传/接入合同 → 条款抽取 → 与客户 Playbook 比对 → 风险清单 + 修订建议 + 引用 → 人工复核 → 导出 Word + 审计日志 | 不做通用法律问答、不做自动签署 |
| v1（3—6 月） | F2/F4 任务型 Agent | 客户条款库/立场库、合同类型模板、版本比对、团队协作、审查时长/漏条款指标 | 不做诉讼策略、不做无复核的自动谈判 |
| v2（6—12 月） | F3 垂直工作流系统 | 嵌入 Word/WPS/OA/合同系统；权限、私有化、按份/席位/年费；与 CLM/ERP 集成 | 不做「大而全」的法务平台 |

**产品架构的最小闭环**：

```
文档接入/解析 → 条款 Schema → 客户 Playbook 检索 → 规则 + 模型审查
→ 风险清单/修订建议（带引用） → 人工复核 → 导出/回写 → 审计日志 → 评测与成本核算
```

**研发重点**（按优先级）：

1. **条款 Schema 与客户 Playbook**：把「这家客户的底线」变成可检索、可版本化的资产；这是护城河，不是模型。
2. **可复核的输出**：每条风险必须给出原文位置、依据（法条/内部条款/先例）、修改建议；没有依据的输出不进报告。
3. **评测集**：100+ 份律师标注合同，测 precision/recall、漏条款率、审查时长；没有评测集不做上线。
4. **责任与安全**：私有化/VPC、不训练客户数据、权限、脱敏、审计日志、人工复核强制。
5. **单位成本**：单份合同的模型/解析/人工复核成本；目标 < 售价 30—50%。

### 5.3 为什么能赢

- **不是模型，是「条款知识 + 复核流 + 责任边界 + 行业模板 + 交付」**；通用模型/大厂能做「读合同」，但做不了「这家律所的立场库 + 可审计的复核流」。[S18][S22][S23]
- **数据飞轮**：客户历史合同与修订记录 → 更好的 Playbook → 更高的采纳率；迁移成本随使用加深。
- **付费意愿**：法律工时贵、外部律师费高、错误代价大；53% 的受访者已看到 ROI，审查/检索是可量化场景。[S10]
- **中国适配**：私有化、信创、按份/按项目计价，比「高客单标准化 SaaS」更可行。[S5][S6]

### 5.4 定价假设（待验证，不是市场价）

- 按份：几十—几百元/份（按合同类型与复杂度分档）。
- 席位：几百元/月/人（团队版）。
- 私有化：年费 + 实施（十万—数十万元级）。
- **原则**：先收费试点（哪怕很低），用真实付费验证；不做「免费 PoC 一年」。

### 5.5 风险与反证

| 风险 | 表现 | 应对/反证 |
| --- | --- | --- |
| 竞争激烈 | 通用法律 AI、合同系统、大厂免费能力 | 窄到 1—2 类合同 + 客户 Playbook + 复核流；若 3 个月内无法差异化，换 B |
| 保密与信任 | 律所不愿把合同给外部模型 | 私有化/VPC、不出域、权限、审计；仍拒绝则换客群 |
| 合伙人分歧 | 一部分合伙人不用、不买单 | 先切「有明确痛点 + 一个 champion」的团队 |
| 准确率不足 | 漏条款、误报多 | 评测集 + 人工复核 + 只输出有依据的建议；达不到阈值不上线 |
| 销售周期长 | 律所决策慢、试用久 | 先做 20—200 人精品所，老板/合伙人直接决策；90 天止损 |

### 5.6 90 天验证计划

- **访谈**：10 场（6 家律所 + 4 家企业法务），每场记录预算、现有替代、决策链、失败经历。
- **付费试点**：3 家 × 4 周，收少量费用；每家选 1 类合同、20—50 份真实合同。
- **指标**：审查时长下降 ≥40%；漏条款率相对人工基线下降；周活 ≥3 次/人；续费意向 ≥2/3；单份成本 < 售价 50%。
- **止损**：3 家都要求免费 >3 个月；或周活 <30%；或单份成本 > 售价 50%；或 90 天无法完成 3 家付费试点 → 换 B/C，不恋战。

## 6. 备选 B：工程投标/施工资料

- **客户**：100—800 人的区域施工/造价/设计企业；优先有大量投标、资料、合同/签证/索赔的企业。
- **痛点**：投标文件编制/核对耗时、截止期硬、资料重复、合同/签证/索赔条款复杂；算量/设计已有专门软件，但「文档链路」仍有空间。[S9][S19]
- **形态**：历史标书库 + 招标文件解析 + 响应点检查 + 文档生成/比对 + 人工复核；先投标，再合同/资料/索赔。
- **为什么是备选**：竞争空隙比法律大，但需要工程行业专家/渠道；图纸/BIM 集成比纯文档难。
- **触发条件**：团队有建筑行业专家/渠道；或法律切口 90 天验证失败。
- **与 A 的关系**：共享「文档解析/比对/生成/复核/审计」能力，只是行业知识与模板不同。

## 7. 备选 C：代账龙头的票据—记账—申报

- **客户**：50—500 人的区域代账龙头；有大量小微客户、票据量大、申报频繁。
- **痛点**：票据录入/对账/申报重复、政策变化、客户咨询；高频、规则清晰、可审计。[S13]
- **形态**：票据识别 → 记账建议 → 申报表生成 → 人工复核 → 客户咨询助手；嵌入现有代账软件/渠道。
- **为什么是备选**：价格战激烈、现有代账软件强势、单户付费低；但渠道明确、复购强、高频。
- **触发条件**：有财税渠道/代账客户资源；或 A/B 都不具备行业 access。

## 8. 明确不做

| 不做 | 原因 |
| --- | --- |
| 通用办公/Agent 平台 | 大厂（WorkBuddy、千问办公、Copilot、Gemini）正面战场，能力/分发/价格打不过[S22][S23] |
| 通用 Bot / 通用法律问答 | 开源与平台快速商品化；无行业知识、无责任链，难收费 |
| 医疗诊断/治疗建议 | 责任、合规、EHR 集成、临床验证门槛高；有医疗资源再考虑 |
| 制造排产/工艺主流程 | OT/IT 集成、零容错、1—4 年成熟周期；不适合软件团队首个产品[S12] |
| 电商内容生成 | 红海、价格战、平台规则变化；不做主方向[S5] |
| 纯项目制定制 | 不可复制、毛利低、验收长；除非是标杆且能产品化 |
| 只做 Demo/大屏 | 一次性预算、无一线使用、无续费 |

## 9. 12 个月路线图

| 阶段 | 时间 | 产品 | 商业 | 关键指标 | 止损 |
| --- | --- | --- | --- | --- | --- |
| 验证 | 0—3 月 | v0 合同审查（1—2 类合同） | 3 家付费试点 | 审查时长 −40%、周活 ≥3 次/人、续费意向 ≥2/3 | 拿不到 3 家付费 → 换 B/C |
| 打磨 | 3—6 月 | v1 客户 Playbook + 团队协作 | 10 家付费、按份/席位 | 单份成本 < 售价 50%、NPS/续费 | 使用率 <30% → 回炉 |
| 复制 | 6—12 月 | v2 嵌入 Word/WPS/OA/CLM；私有化 | 30 家付费、渠道合作 | 续费率 ≥70%、客单提升 | 定制化失控 → 收缩行业 |

> 这是「12 个月做一个窄切口」的路线，不是「12 个月做平台」。平台是结果，不是起点。

## 10. 组织与能力要求

- **行业专家**：法律（合同/条款）、工程（投标/资料）、财税（申报）至少有一个能拍板内容标准的人。
- **交付/客户成功**：垂直产品不是自助 SaaS；需要 onboarding、模板、培训、复盘。
- **私有化/集成**：Word/WPS/OA/CLM、权限、审计、数据不出域。
- **评测/数据**：律师/工程师标注的评测集；没有评测集就没有质量。
- **渠道**：律协/行业软件/代账/工程咨询等渠道，比纯投放更有效。

## 11. 结论置信度与反证

| 结论 | 置信度 | 反证条件 | 下一步 |
| --- | --- | --- | --- |
| 不做通用 Agent/Bot 平台 | 高 | 出现小团队靠通用 Agent 平台规模化盈利的反例 | 持续跟踪 [N2] 与平台动态 |
| 垂直工作流 + 可审计是正确方向 | 高 | 企业大规模接受无监督、无审计的通用 Agent | 跟踪采用率/治理数据[S3][S20] |
| 法律合同是默认首选 | 中 | 3 家付费试点失败；或大厂免费捆绑导致无付费空间 | 90 天验证；失败换 B |
| 工程投标是竞争空隙更大的备选 | 中 | 工程客户不愿为文档付费；或 BIM/图纸集成不可行 | 有渠道时做 5 场访谈 |
| 代账是渠道型机会 | 中低 | 现有代账软件免费覆盖；或价格战导致毛利 <30% | 有渠道时验证 |
| 按份/按任务计价可行 | 中 | 客户只接受席位订阅；或单份成本降不到售价 50% 以下 | 3 家试点报价测试 |

## 12. 一页纸决策摘要（给团队）

1. **方向**：垂直工作流 Agent；不做通用平台/通用 Bot。
2. **第一切口**：法律合同审查 + 条款知识库（默认）；有工程/财税资源则换 B/C。
3. **形态**：F2 文档自动化 → F4 任务型 Agent → F3 垂直工作流系统；人始终在环。
4. **客户**：中型、增长/竞争压力、老板/合伙人能拍板、有核心数据。
5. **收费**：按份/按任务/年费 + 用量；先收费试点。
6. **护城河**：客户 Playbook + 行业知识 + 复核/审计 + 系统集成 + 交付。
7. **12 个月**：3 家付费 → 10 家 → 30 家；续费 ≥70%；单份成本 < 售价 50%。
8. **止损**：90 天 3 家付费试点不成 → 换切口；不定制、不做 Demo、不免费。
9. **最重要的一句**：**Agent 是手段，工作流与责任才是产品。**
