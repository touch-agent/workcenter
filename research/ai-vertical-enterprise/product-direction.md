## 0. 一页纸结论

**一句话：不做通用 Agent / Bot / 办公平台，也不做「行业知识很重、AI 只打辅助」的行业软件；做「AI 承担主要工作量、行业知识可编码、结果可验证」的垂直文档/任务 Agent。**

| 决策 | 结论 |
| --- | --- |
| **首选切口** | 工程投标文件的「合规/完整性检查 + 缺口清单」（默认；AI 做提取/比对，不代写标书）；有法律渠道可做「合同/单据抽取 + 义务清单」；有客服渠道可做「垂直售后」；法律判断型审查、代账记账不做首选 |
| **目标客户** | 工程 100—800 人区域施工/造价/设计企业，投标团队 3—10 人；合同抽取面向 20—200 人精品所 / 100—500 人企业法务部；垂直客服面向电商/SaaS 客服团队 |
| **产品形态** | v0 上传招标 + 投标文件 → 要求矩阵/缺口清单 → 人工复核 → 审计日志（无需 IT）；v1 客户检查清单/历史标书库；v2 嵌入 Word/WPS/投标系统（有 IT 时可选） |
| **收费** | 按标 / 按项目 / 年费 + 用量；先收费试点，不做免费 PoC |
| **目标** | 90 天 3 家付费试点；12 个月 30 家付费、续费 ≥70%、检查时长 −60%、AI 首轮覆盖 ≥70%、单标成本 < 售价 50% |
| **明确不做** | 法律判断型合同审查、代账记账、通用桌面 Agent、通用办公助手、通用 Agent 平台、通用 Bot、医疗诊断、制造排产主流程、电商内容红海、纯项目制定制 |
| **止损** | 90 天拿不到 3 家付费试点，或 AI 首轮覆盖 <70% → 换备选（合同抽取/垂直客服），不改「AI 做主体、人审例外」方向 |

> 以上数字是**验证目标**，不是市场事实；定价与指标需在试点中校准。

## 1. 为什么现在：供给侧的三个变化

### 1.1 Agent 正在从「问答」变成「常驻执行」，编排层在商品化

- DeepSeek 开源的 Super-agent 原型把「Router/Worker、事件驱动、订阅直通、存算分离、Watchdog」做成可复用的调度架构；实验 p50/p95 为 12.4/15.7 分钟，对比单会话 p95 29.5 分钟。团队自称是原型，不是产品。[N2]
- Vercel 发布 agent-desktop，让 Agent 操作用户整台电脑，而不只是浏览器。[N2]
- 以 IM/PR 为入口的常驻 Agent 开始成为产品形态：可被 @、可订阅线程、可主动执行任务（如 DeepSeek 原型）。[N2]

**产品含义**：多 Agent 编排、常驻执行、computer-use 会逐渐变成基础设施，而不是差异化产品。**不要做「更强的通用 Agent 平台」**；把编排能力当作底座，去做一个具体工作流里的可靠交付。

### 1.2 资本周期收紧，「廉价 token」不能当作长期假设

- OpenAI 把本轮融资目标从 300 亿美元下调至约 200 亿美元，估值从 1.4 万亿降至 1.25 万亿美元；纳斯达克 100 单日下跌 3.5%、10 月累计跌 6.65%。[N1]
- 超大规模厂商的算力承诺与债务继续膨胀，行业对「算力—收入—更高估值」的闭环开始重新定价。[N1]
- 直接后果：便宜推理的补贴来自便宜资本；融资收紧后，模型价格战会放缓，高频、高 token 场景的配额与价格可能收紧。[N1]

**产品含义**：不要做「token 消耗大、价值不可计量」的通用聊天/写作；从第一天就按任务核算成本，设计按份/按任务/按结果的计价，保证单位经济成立。

### 1.3 能力越强，责任、安全、审计越贵

- Wiz 记录 AI 开发平台的「黑色十月」：至少 9 家平台披露安全事件，多指向凭据窃取、agent swarm 攻击与「蒸馏」入侵；两起案例在 30/13 小时内发起约 80 万/170 万次 Bedrock 调用，标价计费超 10 万美元。[N1]
- 企业侧：36% 没有正式 AI 治理，88% 已让 AI 在无人工签核下做决定；97% 高管称部署 Agent，但只有 52% 员工真正使用，29% 承认抵制。[S3][S20]
- 医疗、法律、金融的顾虑集中在幻觉、隐私、权限与责任归属。[S10][S11][S18]

**产品含义**：**信任层不是「功能」，是产品的一部分**：权限、审计、复核、引用、数据隔离/私有化（可选）、责任边界。谁能让「不敢用」的行业敢用，谁就能收溢价。

> 注：OpenClaw、WorkBuddy、Personal Agent 集群、DeepSeek super-agent 的形态演化，已整理为 [trend-agent-evolution.md](trend-agent-evolution.md)（[N3]）。下面的 1.4—1.6 只取与产品方向直接相关的结论；外部事实沿用该整理稿，未重新核验。

### 1.4 三类趋势对产品研发的含义

| 趋势 | 代表 | 可借的力 | 不要做的陷阱 |
| --- | --- | --- | --- |
| computer-use / 桌面 Agent | OpenClaw[N3]、Vercel agent-desktop[N2] | 把「操作电脑」降级为垂直工作流里的一个工具调用；让 Agent 去填表、导数据、改文档 | 做通用桌面 Agent：权限、安全、可靠性、跨软件兼容会被平台和大厂拖死 |
| 办公 Agent / 企业上下文 | WorkBuddy[S23]、千问办公[S22] | 借办公入口分发；把产品嵌进 IM/文档/审批流 | 做通用办公助手：被大厂免费捆绑，独立产品没有留存理由 |
| Bot / IM 入口 | 各类 bot[N3]、DeepSeek 常驻 Agent 原型[N2] | 用 IM/PR 作为低门槛入口；让用户在原有工作流里 @ 一下就用 | 把「bot」当产品：没有行业知识、复核、审计，就只是一个更贵的聊天框 |

**结论**：这三类趋势都在把「通用能力」变成基础设施。产品研发要借它们的力（入口、编排、工具调用），但**产品本体必须是垂直工作流 + 责任链**，否则就会被商品化。

### 1.5 四代 Agent 的形态演化：从 OpenClaw 到 super-agent

> 完整整理见 [trend-agent-evolution.md](trend-agent-evolution.md)（[N3]）；这里只取与产品方向直接相关的结论。

| 代际 | 样本 | 形态 | 证明了什么 | 暴露的问题 |
| --- | --- | --- | --- | --- |
| 能力验证 | OpenClaw（2026-01） | 开源、可自托管的个人 Agent | Agent 可以操作真实电脑；IM 可成为入口；Skills 可扩张 | 安全边界、长任务可靠性、运维责任在用户 |
| 组织化 | WorkBuddy（2026-03，10 月企业版） | 办公智能体平台 | 企业要的是身份/权限/审计/私有化；个人提效 ≠ 组织回报 | 系统难打通、不敢放权、不好管控、难以常驻 |
| 产品化 | Personal Agent 集群（2026-08/09） | 常驻个人 Agent | always-on 形态成立；任务列表/审批/记忆成为主界面 | 可靠性、常识、成本、信任；同质化快 |
| 基础设施化 | DeepSeek super-agent（2026-10） | Router/Worker 运行时 | 调度、订阅、隔离、授权可以做成基础设施 | 原型；单 Router 扩展、多租户、凭据风险未解 |

**六条规律**：委托变长决定形态；交互面外移、Session 退化为实现细节；执行环境独立化；每次能力跃迁补一层治理；计费单位随委托长度上移；组织两端（超级个体/超级组织）同时生长。[N3]

### 1.6 趋势结论 → 产品决策

> A = 入口型 Copilot，B = 交付型数字员工，C = 底座型 Agent 运行时；定义见 [trend-agent-evolution.md](trend-agent-evolution.md) 第 4 节。

| 趋势结论 | 对我们的含义 | 选择 |
| --- | --- | --- |
| 竞争从模型转向运行时/治理 | 不自研通用 runtime；用现成模型与编排，把治理做进垂直产品 | 做 B 交付型数字员工，不做 C 底座 |
| 委托变长、界面外移 | 主界面是任务列表/审批/执行记录；IM/PR 是入口，不是聊天框 | 投标检查队列 + 复核 + 审计日志 |
| 每次能力跃迁补治理 | 审批、身份、审计、回滚从 v0 就有，而不是上线后再补 | 先收费试点，先过安全评审 |
| 计费单位随委托长度上移 | 按份/任务/结果计价，不按 token | 按份/按任务/年费 + 用量 |
| 企业从可度量、可审计的单点开始 | 选高频、必经、可度量、可审计的楔子，不做通用助手 | 工程投标合规检查；合同抽取/客服备选 |
| B 被低估、A 被高估、C 壁垒最高 | 做垂直交付，不做入口 Copilot/通用平台 | B；不碰 A/C |

**取舍说明**：趋势研究说「运行时与治理是下一个战场」，但这是对大厂/平台团队说的。创业团队如果去做 C（通用运行时），会同时面对 WorkBuddy WMA、云厂商和开源的竞争；做 A（入口 Copilot）会被平台吞并。最可守的是 B：用别人的 runtime，把行业知识、复核、审计和交付做成产品。这与第 2、3 节的垂直判断一致。

**不做的边界**：这四代样本正好对应四类陷阱——OpenClaw 式通用桌面 Agent 的安全/运维责任、WorkBuddy/千问式通用办公助手的入口战场、Personal Agent 式通用 Bot 的同质化、无监督自主（G2 仅 7% 买家愿意给完全自主权）。[N3]

### 1.7 切口重筛：AI 价值占比优先

> 这一节是对原结论的修正：法律合同审查、代账被降级，不是需求不真，而是「行业知识很重、AI 只占小部分」不符合 AI 产品的前提。

**两个测试**：

1. **去掉 AI 测试**：如果没有 AI，产品还能交付大部分价值吗？能 → 它更像行业软件/服务，不是 AI 产品。
2. **新手测试**：一个有一周培训、拿着检查清单的新人，能用它完成 70% 的工作吗？不能 → 行业知识是主要壁垒，AI 只是辅助。

**重筛结果**：

| 切口 | AI 价值占比 | 行业知识 | 原结论 | 新结论 |
| --- | --- | --- | --- | --- |
| 法律合同审查 | 低—中（判断/责任为主） | 高（执业经验） | 首选 | 不做首选；只保留「抽取 + 义务清单」 |
| 代账 | 低（规则/软件为主） | 高（财税规则） | 备选 | 不做首选 |
| 工程投标合规检查 | 高（提取/比对为主） | 中（明示规则/清单） | 备选 | **首选** |
| 合同/单据抽取 + 义务清单 | 高（抽取/比对） | 中（客户 Playbook） | — | 备选：合同抽取 |
| 垂直客服/售后 | 高（问答/工单闭环） | 中（产品/订单知识） | — | 备选：垂直客服（有渠道） |

**判断**：不是「行业知识不重要」，而是**行业知识必须可编码、可评测、可从客户资料中学习**；如果每个客户都要靠一个资深专家才能用，AI 就只是辅助，产品会退化成咨询/外包。新的评分把「AI 价值占比」放到 30% 权重，见第 4 节。

### 1.8 客户没有技术团队：业务人员可用是硬约束

> 用户补充的约束（2026-11-02）：客户没有技术团队，产品主要面向业务人员。它比「功能强」更优先：如果业务人员不能独立用起来，产品就卖不动。

- **业务可用性门槛**：业务人员经过约 1 小时培训，能独立完成 80% 操作；不需要 IT 部署、接口开发、数据治理。
- **产品形态含义**：turnkey SaaS / 桌面工具；上传/导出；内置模板与检查清单；厂商托管运维；私有化是可选，不是前提。
- **切口含义**：优先「文档进、清单出」的场景（投标合规、合同抽取、客服售后）；排除需要 OT/EHR/ERP 深度集成的场景（制造排产、医院 EHR、大型 ERP）。
- **商业含义**：按业务用户/按标/按任务计价；卖给业务负责人，不卖「平台/API」；onboarding 由客户成功完成，不依赖客户 IT。
- **验证问题**：让 3 位业务人员在没有 IT 支持的情况下，独立完成一次真实任务；完成率 <80% 或需要 IT 介入 → 产品形态不合格。

## 2. 为什么是垂直：需求侧的四条硬约束

1. **企业不为「AI」付费，为「被解决的工作」付费。** 买家语言是工时、单据、合规、回款，不是模型能力。[S3][S5]
2. **采用面宽、嵌入浅。** 近九成企业至少一个职能用 AI，44% 全企业部署，但只有 46% 嵌入核心工作流；Menlo 称仅 16% 部署是真 Agent。[S1][S2][S3]
3. **试点到生产是死亡谷。** 约 95% 的大型企业生成式 AI 试点没有可测量损益影响；员工实际使用率 52%，29% 抵制。[S20]
4. **中国第一约束是价格与交付。** 小微净利率 4.4%，58.5% 因价格放弃/停止续费；中小企业 AI 渗透率约 15%，68% 停留在轻量场景；政策方向是「小快轻准」、可私有化、可迁移。[S5][S6]

**结论**：通用能力会被大厂与开源吃掉；独立产品最可守的位置是 **「可编码的行业规则 + 可复核的输出 + 责任链 + 业务人员可用」** 四件事的组合。[S18][S19][S21][S22][S23]

## 3. 交汇点：趋势 × 需求 = 产品机会地图

| 供给侧趋势 | 需求侧约束 | 产品含义 |
| --- | --- | --- |
| 通用 Agent/编排能力商品化 | 企业不为「自主」付费，为「结果」付费 | 不做通用 Agent，做垂直工作流里的任务 Agent |
| computer-use / 桌面 Agent 兴起 | 企业要求权限、审计、可回滚 | 先做「可复核的文档/数据任务」，不碰无监督的物理/资金动作 |
| 模型价格与配额不确定 | 中国客户价格敏感、要按效果 | 按份/按任务计价，单位任务成本可核算 |
| 大厂把通用助手捆进办公套件 | 通用问答/写作被免费化 | 避开 F1 通用副驾，切 F2/F3 的行业最后一公里 |
| 安全事件与合规压力上升 | 医疗/法律/金融「不敢用」 | 权限、审计、数据隔离成为卖点；私有化可选 |

**一句话**：**Agent 是实现手段，工作流与责任才是产品。** 产品研发的重点不是「让 Agent 更自主」，而是「让一个具体工作流更可靠、更可审计、更省钱」。

**研发投入原则**：不自研基础模型/通用 Agent 框架；用现成模型与编排，把工程投入放在行业知识、评测集、复核/审计与交付；集成只在客户有 IT 时作为可选项。

## 4. 候选切口：按「AI 价值占比」重排

> 评分为 1—5 的判断值，不是统计测量；权重：AI 价值占比 30%、行业知识可学习性 20%、可验证性 20%、付费意愿 15%、竞争空隙 10%、交付可行性 5%。旧版把「行业知识护城河」权重放得过高，导致法律/代账排到前面；新版先问「AI 是不是主要生产力」。
>
> **业务可用性门槛（先过门槛，再评分）**：业务人员经 1 小时培训可独立完成 80% 操作，无需 IT 部署/集成。工程投标、合同抽取、垂直客服通过；制造（OT）、医疗（EHR）、通用平台不过；法律审查/代账虽可通过，但 AI 占比低。

| 切口 | AI 价值占比 | 知识可学习性 | 可验证性 | 付费意愿 | 竞争空隙 | 交付可行性 | 加权分 | 判断 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 工程：投标文件合规/完整性检查 | 4 | 4 | 5 | 4 | 4 | 4 | **4.20** | 默认首选；AI 做提取/比对，行业知识是明示清单 |
| 2 合同/单据抽取 + 义务清单 | 4 | 4 | 5 | 3 | 3 | 4 | **3.95** | 法律渠道备选；只做抽取/比对，不做法律判断 |
| 3 垂直客服/售后 | 5 | 4 | 3 | 4 | 2 | 3 | **3.85** | AI 占比最高，但竞争/价格压力大；有渠道再做 |
| 4 制造：质检/预测维护 | 4 | 2 | 4 | 5 | 4 | 2 | **3.65** | 价值高；OT/硬件/零容错，落地慢 |
| 5 电商：内容/运营 | 5 | 4 | 3 | 2 | 1 | 5 | **3.55** | AI 占比高，但红海/平台规则，不做主方向 |
| 6 通用 Agent/Bot | 5 | 4 | 3 | 2 | 1 | 4 | **3.50** | 大厂/开源正面战场，不做 |
| 7 医疗：病历/环境记录 | 4 | 2 | 3 | 4 | 3 | 2 | **3.20** | 需求最真；合规/EHR/责任重，有资源再做 |
| 8 法律：合同审查 + 条款知识库 | 2 | 2 | 4 | 4 | 2 | 4 | **2.80** | AI 只占小部分；不做首选 |
| 9 代账：票据—记账—申报 | 2 | 2 | 5 | 3 | 2 | 3 | **2.80** | 规则/软件为主；不做首选 |

**读法**：

- **工程投标第一，但证据最薄**：投标合规的痛点、付费意愿、AI 覆盖率都还没有一手验证；它赢在「AI 做的是读/比/列缺口，不是替人做专业判断」。90 天内必须验证 AI 首轮覆盖 ≥70%。
- **合同抽取是法律里唯一符合 AI 价值占比的切口**：抽取当事人/日期/续约/责任/付款/终止，和客户 Playbook 比对，输出义务/风险清单；法律判断仍由律师做。若法律渠道强，合同抽取可以先行。
- **垂直客服的 AI 占比最高，但竞争最凶**：客服/售后已被平台和 SaaS 厂商重兵投入；没有垂直数据/渠道，不建议作为第一切口。
- **法律审查/代账不是需求假，而是 AI 占比低**：法律判断靠执业经验，代账靠规则与现有软件；AI 是 OCR/检索/草稿，价值小部分。做它们会把公司做成行业软件/服务商，而不是 AI 产品。
- **制造/电商/医疗/通用 Agent 不作为主方向**：制造/医疗交付门槛高，电商/通用 Agent 是红海/平台战场。

## 5. 首选方向：工程投标文件的合规/完整性检查

### 5.1 客户与切口

- **客户**：100—800 人的区域施工/造价/设计企业；投标团队 3—10 人；每年 >20 个标；优先有「废标/返工/资质过期/漏项」历史的团队。
- **切口**：只做**投标文件的合规/完整性检查**，不做标书代写、不做技术方案评分、不做报价策略。解析招标文件，抽取资格/格式/响应点/日期/盖章等硬性要求，逐条比对投标文件，输出**缺口清单 + 原文引用**。
- **用户**：投标专员/投标经理（每天用）；投标负责人/老板（买单）。
- **客户约束**：没有技术团队；v0 只做 web 上传/导出，不做接口/私有化部署；厂商托管、数据隔离；私有化仅作为大客户可选项，由厂商交付。
- **痛点**：一份标书几百页，要求分散在招标文件各处；人工逐条核对 1—3 天；漏一项就可能废标；截止期硬、返工成本高。建筑 AI 采用面已不低，但嵌入日常仍少、且「零容错」。[S9][S19] 投标合规的具体痛点与付费意愿仍需一手验证。
- **现有替代**：手工 checklist、标书软件、投标咨询、通用大模型（不可追溯、不可审计）。

### 5.2 产品形态（12 个月）

| 阶段 | 形态 | 关键能力 | 不做什么 |
| --- | --- | --- | --- |
| v0（0—3 月） | F2 文档自动化 | web 上传招标 + 投标文件 → 要求矩阵 → 缺口清单（带原文引用）→ 人工复核 → 导出 + 审计日志；无需 IT | 不代写标书、不做技术评分/报价 |
| v1（3—6 月） | F2/F4 任务型 Agent | 客户检查清单/模板库、历史标书复用、版本比对、团队协作、检查时长/漏项指标；可选 Word/WPS 导出 | 不做投标策略、不做报价；不强制装插件 |
| v2（6—12 月） | F3 垂直工作流系统 | 按标/年费；权限、审计、厂商托管；只有客户有 IT/标书系统时才做集成 | 不做「大而全」的投标平台；不把集成当前提 |

> **AI 首轮覆盖**：AI 第一轮就能给出、且复核后不需要从头重做的检查项占比；不是「AI 参与过」的比例。这是判断「AI 是否做主体」的核心指标。

**产品架构的最小闭环**：

```
招标文件解析 → 要求 Schema（资格/格式/响应点/日期/盖章）
→ 投标文件解析 → 逐条比对 → 缺口清单（带原文引用）
→ 人工复核 → 导出/回写 → 审计日志 → 评测与成本核算
```

**研发重点**（按优先级）：

1. **要求 Schema 与客户检查清单**：把「这家公司/这个地区的投标规则」变成可版本化、可评测的资产；这是护城河，不是模型。
2. **每条缺口必须带原文引用**：招标文件第几页/第几条、投标文件第几页；没有依据的提示不进清单。
3. **评测集**：50—100 对真实招标/投标文件，由投标专家标注；测召回/精确、漏项、检查时长；没有评测集不上线。
4. **安全与托管**：标书含报价/资质/客户信息；厂商托管 + 数据隔离、权限、脱敏、审计、不训练客户数据；私有化仅作为大客户可选。
5. **单位成本**：单标解析/模型/人工复核成本；目标 < 售价 50%。

### 5.3 为什么能赢

- **AI 做的是「读几百页、逐条比对、列缺口」**，不是替人做专业判断；这是 AI 最擅长、且价值占比最高的部分。
- **行业知识是明示规则 + 客户 checklist**，可从招标文件和历史标书学习；一个投标专员经短培训就能用，不需要资深专家逐标把关。
- **数据飞轮**：客户历史标书/检查清单 → 更好的要求 Schema → 更高覆盖率；迁移成本随使用加深。
- **付费意愿**：一次废标的代价远高于工具费；截止期硬、责任明确；比法律/代账更容易算 ROI。
- **竞争空隙**：标书软件/造价软件强在「编制/算量」，AI 原生「合规检查」是窄缝；大厂不专注。
- **业务人员可用**：投标专员上传/复核/导出，不需要 IT 部署或接口；这是客户没有技术团队时的前提。

**但这是本报告证据最薄的推荐**：需要 90 天验证 AI 首轮覆盖 ≥70%、3 家付费、检查时长 −60%；达不到就换备选（合同抽取/垂直客服）。

### 5.4 定价假设（待验证，不是市场价）

- 按标：几百—几千元/标（按页数、标段、复杂度分档）。
- 年费：3—10 万元/年（含 N 个标/月、检查清单、审计）。
- 私有化（可选）：仅大客户，年费 + 实施（十万—数十万元级），由厂商交付。
- **原则**：先收费试点（哪怕很低），用真实付费验证；不做「免费 PoC 一年」。

### 5.5 风险与反证

| 风险 | 表现 | 应对/反证 |
| --- | --- | --- |
| 招标文件格式多变/扫描件 | 要求抽取失败、漏项 | 50—100 对评测集；提取准确率 <80% 不做 |
| 客户说「我们有 checklist」 | 不愿为检查付费 | 把 checklist 产品化，卖覆盖率/时长/审计；仍不愿付费则停 |
| 误报多 | 复核者不信任、回到手工 | 每条缺口带原文引用；精确率 >80%；人审例外 |
| 投标频率低/季节性 | 单位经济不成立 | 只做 >20 标/年客户；<10 标/年不做 |
| 标书软件/广联达捆绑 | 免费功能挤压 | 窄到合规/证据/审计；被免费捆绑则换备选（合同抽取） |
| 数据敏感 | 不愿上传标书 | 厂商托管 + 数据隔离/审计；私有化仅作为大客户可选，由厂商交付 |
| 客户没有 IT，无法私有化 | 安全评审要求本地部署 | 先做托管 + 数据隔离；若必须本地，客户通常有 IT，按项目评估，不把私有化当前提 |

### 5.6 90 天验证计划

- **访谈**：10 场（5 家施工/造价/设计企业，投标经理/投标负责人），记录投标频率、废标/返工经历、现有 checklist、预算与决策链。
- **付费试点**：3 家 × 4 周，收少量费用；每家 20—50 个真实标。
- **指标**：检查时长 −60%；漏项率相对人工基线下降；**AI 首轮覆盖 ≥70%**；误报率 <20%；周活 ≥3 次/人；续费意向 ≥2/3；单标成本 < 售价 50%。
- **业务可用性**：3 位投标专员在没有 IT 支持的情况下，独立完成一次真实标检查；完成率 <80% 或需要 IT 介入 → 产品形态不合格。
- **止损**：3 家都要求免费 >3 个月；或 AI 首轮覆盖 <70%；或用户仍从头手工检查；或误报 >30%；或 90 天无法完成 3 家付费试点 → 换备选（合同抽取/垂直客服），不恋战。

## 6. 备选：合同/单据抽取 + 义务清单

- **客户**：20—200 人精品所、100—500 人企业的法务部；优先合同量大、有模板/Playbook、有法务运营岗位的组织。
- **切口**：抽取当事人、日期、续约、责任、付款、终止、保密等字段；与客户 Playbook 比对；输出**义务/风险清单 + 原文引用**；法律判断仍由律师/法务做。不做法律意见、不做自动谈判。
- **AI 角色**：抽取/比对是主要工作量；这是法律里唯一符合「AI 价值占比」的切口，因为它把「读合同、找条款、对底线」交给 AI，而不是让 AI 做执业判断。
- **客户约束**：法务/律师上传/导出；不依赖 CLM/ERP 集成；CLM 集成只作为可选。
- **为什么是备选**：法律客户信任/竞争/CLM 现有玩家；若投标合规验证失败且有法律渠道，再上合同抽取。
- **定价**：按份/年费；先收费试点。
- **触发条件**：有法律行业 access；5 场法务/律师访谈确认「抽取+义务清单」比「审查意见」更愿意付费。

---

## 7. 备选：垂直客服/售后

- **客户**：垂直电商/SaaS 的客服团队，10—50 人坐席，工单量大、重复问题多。
- **切口**：用产品文档/订单/物流数据，让 AI 解决重复咨询/退换货/工单分派；复杂/情绪/例外转人工。按解决量/坐席收费。
- **AI 角色**：AI 占比最高；行业知识是产品/订单知识，可从文档与历史工单学习；效果可测（自助解决率、CSAT、人工时长）。
- **客户约束**：客服主管配置 FAQ/订单数据；不需要开发；平台接入由厂商完成。
- **门槛风险**：若订单/物流数据必须客户 IT 开接口才能拿到，D 不过「无 IT 依赖」门槛；先用「产品文档 + 人工上传订单/导出」验证。
- **为什么是备选**：平台/客服 SaaS 重兵投入，价格战；没有垂直数据/渠道，不建议作为第一切口。
- **触发条件**：有垂直客服渠道/存量客户；5 场客服负责人访谈确认「重复问题占比 >50%」。

## 8. 为什么法律判断型审查、代账不做首选

| 切口 | 需求为什么真 | 为什么不做首选 | 如果要做 |
| --- | --- | --- | --- |
| 法律合同审查（判断型） | 合同量大、错误代价高、付费意愿有[S10] | 判断靠执业经验；AI 做检索/草稿，价值只占小部分；责任在律师；竞争激烈 | 只做合同抽取/义务清单，不做法律意见 |
| 代账/记账 | 高频、规则清晰、可审计[S13] | AI 是 OCR/分类，规则与现有软件是主体；价格战；代账软件强 | 作为渠道型功能/服务，不做独立产品 |

**这不是否定需求，而是否定「用 AI 产品去切一个 AI 只占小部分的价值链」。** 如果团队的核心能力是法律/财税交付，做服务/外包可能更顺；如果要做 AI 产品，必须让 AI 承担主要工作量。

## 9. 明确不做

| 不做 | 原因 |
| --- | --- |
| 通用办公/Agent 平台 | 大厂（WorkBuddy、千问办公、Copilot、Gemini）正面战场，能力/分发/价格打不过[S22][S23] |
| 通用 Bot / 通用法律问答 | 开源与平台快速商品化；无行业知识、无责任链，难收费 |
| 法律判断型审查 | AI 只占小部分；责任在律师；会把产品做成行业服务 |
| 代账/记账 | 规则/软件为主；价格战；AI 是 OCR/分类；现有代账软件强 |
| 医疗诊断/治疗建议 | 责任、合规、EHR 集成、临床验证门槛高；有医疗资源再考虑 |
| 制造排产/工艺主流程 | OT/IT 集成、零容错、1—4 年成熟周期；不适合软件团队首个产品[S12] |
| 电商内容生成 | 红海、价格战、平台规则变化；不做主方向[S5] |
| 纯项目制定制 | 不可复制、毛利低、验收长；除非是标杆且能产品化 |
| 需要客户 IT 深度集成的项目 | 客户没有技术团队；项目制、周期长、不可复制 |
| 私有化重项目 | 交付重、毛利低；除非大客户且厂商托管 |
| 只做 Demo/大屏 | 一次性预算、无一线使用、无续费 |

## 11. 组织与能力要求

- **行业专家**：投标经理/造价工程师（懂招标文件、评标规则、废标点）至少一个能拍板内容标准；法律/财税专家作为合同抽取/渠道功能的备选，不是首选。
- **交付/客户成功**：垂直产品不是自助 SaaS；需要业务人员 onboarding、检查清单配置、培训、复盘；不依赖客户 IT。
- **部署/运维**：厂商托管、数据隔离、权限/审计；私有化只作为大客户可选项，由厂商交付；集成不是前提。
- **评测/数据**：投标专家标注的 50—100 对招标/投标文件；没有评测集就没有质量。
- **渠道**：建筑行业协会、投标代理、造价咨询、标书软件合作，比纯投放更有效。

## 13. 一页纸决策摘要（给团队）

1. **方向**：AI 原生的垂直文档/任务 Agent；AI 做主体，人审例外；不做通用平台/通用 Bot。
2. **第一切口**：工程投标合规/完整性检查（默认）；合同/单据抽取、垂直客服作为备选（看渠道）。
3. **形态**：F2 文档自动化 → F4 任务型 Agent → F3 垂直工作流系统；人始终在环。
4. **客户**：100—800 人施工/造价/设计企业，投标团队 3—10 人；合同抽取面向 20—200 精品所/100—500 企业法务；垂直客服面向电商/SaaS 客服。
5. **收费**：按标/按项目/年费 + 用量；先收费试点。
6. **护城河**：客户检查清单/历史标书 + 评测集 + 复核/审计 + 系统集成 + 交付；不是「行业知识」四个字本身。
7. **12 个月**：3 家付费 → 10 家 → 30 家；续费 ≥70%；单标成本 < 售价 50%。
8. **止损**：90 天 3 家付费试点不成，或 AI 首轮覆盖 <70% → 换备选（合同抽取/垂直客服）；不定制、不做 Demo、不免费。
9. **最重要的一句**：**AI 必须做主体，行业知识必须可编码；否则那是行业软件/服务，不是 AI 产品。**
10. **客户约束**：没有技术团队；产品必须 turnkey、业务人员自助；不卖平台/API/重集成。
